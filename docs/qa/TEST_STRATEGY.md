# Test strategy

The design concentrates risk in three places: the **workflow engine** (determinism), **claims/leases** (concurrency), and the **daemon ↔ orchestrator contract** (delivery under failure). Tests target those.

| Layer | What | Tooling | Where |
|---|---|---|---|
| Unit | Workflow validator (one failing fixture per rule); FSM `apply()` (table-driven over every transition of both reference workflows); idempotency-key derivation; column mapping | vitest | `packages/shared`, `packages/web` |
| Property | Random event sequences into `apply()` never produce an undefined state, never exceed retry caps, always end able to reach terminal/human | vitest + fast-check | `packages/shared` |
| Integration (DB) | Migrations; transactional apply + outbox; dispatcher re-send after crash; claim query with `SKIP LOCKED` under N concurrent claimers (M2); reaper + fencing (M2) | vitest + real Postgres (docker-compose; **no SQL mocks**) | `packages/orchestrator` |
| Integration (daemon) | Daemon against a fake orchestrator WS: register, heartbeat, start → worktree, command runner, semaphore, dedupe `command_id`, reconnect + seq replay (M2) | vitest | `packages/daemon` |
| Contract | Protocol message schemas (zod in `shared`) used by both sides; snapshot of message catalog | vitest | `packages/shared` |
| E2E | Postgres + orchestrator + daemon + **fake Claude** (scripted binary honouring ADR-0005 contract) on a fixture repo: happy path; build/test fail-then-pass; retries exhausted → needs_input; ask_user answered via REST; no outcome reported → one nudge → needs_input (U-028). Optional `E2E_REAL_CLAUDE=1` | vitest or playwright (UI), `pnpm test:e2e` | `e2e/` |
| Chaos (M2) | **Laptop sleep**: SIGSTOP daemon past lease grace → requeue with token+1 on second daemon → SIGCONT → stale events rejected + kill. Orchestrator kill -9 mid-transition. WS drop < grace (no lost session) | e2e harness | `e2e/chaos/` |

## Principles
- The fake Claude is a first-class test fixture. Most E2E runs never call the real model: deterministic, fast, free.
- Every bug fix lands with a test that would have caught it.
- Flaky tests are bugs. Quarantine them with a TD-### row, never by silently retrying.

## Running on a shared machine (M2-T31)
Many worktrees, conductor sessions and Claude subagents run gates on the same box. Unthrottled, a dozen parallel runs pushed the load average past 40 on 4 cores and tests failed on their 5 s timeouts. So every vitest run (root and e2e configs, via `globalSetup`) and `pnpm lint` takes one of `CONDUCTOR_TEST_SLOTS` (default 2) machine-wide slots first (`scripts/test-slot.js`), and vitest's `maxWorkers` is the CPU count divided by the slots.
- A slot is a localhost port (`CONDUCTOR_TEST_SLOT_PORT`, default 54330, +1 per slot). The OS frees it when the holder exits, even on SIGKILL, so there's no stale lock.
- A waiter prints who holds the slots every 30 s and gives up after `CONDUCTOR_TEST_SLOT_WAIT_S` (default 1800) with the holders in the error.
- A holder sets `CONDUCTOR_TEST_SLOT_HELD=1` for its children, so nested runs don't deadlock. Watch mode takes no slot. `CONDUCTOR_TEST_SLOTS=0` turns the limit off (a dedicated CI runner).

## Write small, fast tests
Slow tests slow every branch, every agent and every PR, so a test earns its cost.
- **Default to a unit test of a pure function**: input in, output checked, no I/O. Pull the logic you want to test out of the code that does I/O (as `apply()` is pulled out of the engine, and arg builders out of the drivers) and test it directly.
- **Spawning a process is the expensive thing**: a `node`, `git`, `gh` or `powershell.exe` child costs ~50–200 ms on Linux and ~1 s on Windows. The three slowest daemon files spend 140–205 s each on Windows doing this. Spawn only when the process boundary is what's under test (argument quoting, exit codes, signals, the hook contract), with one test per behaviour, not one per case. Test the cases through the pure function.
- **Prefer fakes in memory** to real servers, real repos and real timers: the fake orchestrator, a stub driver, `vi.useFakeTimers()`. Build a git repo once per file (`beforeAll`), not per test, when a real one is needed.
- **No sleeps.** Wait on the event, or use fake timers.
- **A new slow test needs a reason**, in a comment at the top of its `describe`: what only a real process, DB or browser can show. It goes in `SLOW_TIERS` (below). If it touches the OS it also runs on Windows, where it costs ~10× more.

## Keeping the suite fast (M2-T33)
- **Tiers** (`scripts/test-tiers.js`): `pnpm test` skips the slow tiers (web jsdom, daemon tests that drive real git / node children, orchestrator Postgres tests, engine property tests) unless the branch changed something they test since its merge-base with `main` (the newer of the merge-bases with local `main` and `origin/main`, so a worktree's stale `main` doesn't run everything). It prints what it skipped. Global files (configs, test helpers), test files named on the command line, or no merge-base run everything. A `pnpm-lock.yaml` change counts only against the packages whose resolved dependency closure it changed (`scripts/test-lockfile.js`), as if their `package.json` changed; a root-toolchain or settings change still runs everything. A `package.json` change runs its own package's tier (shared's runs every tier). `pnpm test:all` (`vitest run --mode all`, used by `scripts/ci.sh` locally and on `main`) always runs every tier; on a PR, CI runs the tiered `pnpm test` against the PR base (`CONDUCTOR_CI_TIERED=1`), and the property tests at their full run counts (a fifth otherwise; they are unseeded, so every run still explores new cases). A new expensive test file belongs in `SLOW_TIERS`.
- **Rust and e2e gates** (`scripts/ci-affected.js rust|e2e`): on a PR, `scripts/ci.sh` also skips `cargo clippy` + `cargo nextest` when the diff doesn't reach Rust (crates, Cargo files, the toolchain, `packages/shared`, CI itself), and the e2e suite when it doesn't reach the stack (e.g. docs, markdown, `packages/web`, `deploy/`). Without `--base` they diff against the merge-base with `main`; an unknown diff runs everything. `main`, a dispatch and a laptop run both. The e2e suite in CI runs the debug daemon nextest built (`CONDUCTOR_E2E_DAEMON_BIN=target/debug/conductor-daemon`); when nextest was skipped, `cargo nextest run --no-run` builds it with the same features, so the cached deps are reused. The release profile is proven by `daemon-rust.yml`, `daemon-dist.yml` and the deploy.
- **No per-file isolation**: projects run with `isolate: false`, so a worker imports each module once (`shared` went from 61 s to 21 s). A file that mocks modules (`vi.mock` / `vi.doMock`) is detected when the config loads and runs in a `<package>-isolated` project; `--project '<package>*'` selects both. Fake timers and spies must be restored per test, as they already are.
- **Quarantine (WF-T05)**: a known-flaky test is listed in [`docs/tracking/FLAKY.md`](../tracking/FLAKY.md), the one list. A listed TypeScript file leaves every package project (so `pnpm test` / `test:all` skip it) and runs only in the opt-in `quarantine` vitest project (`pnpm vitest --project quarantine` or `pnpm test:quarantine`; `retry: 2`, `CONDUCTOR_QUARANTINE_RETRY=0` for none). A listed Rust test carries `#[ignore = "flaky: see FLAKY.md"]` (run with `cargo test -p conductor-daemon -- --ignored`). The nightly [`quarantine.yml`](../../.github/workflows/quarantine.yml) runs them all without retries and reports each row (passed, still failing, infrastructure, overdue). `scripts/test-flaky.test.js` keeps the list and the `#[ignore]` markers in sync. Every row has an owner ticket and a fix-by date; past it, the test is fixed (row deleted) or deleted. If only one case of a large file flakes, move it to a sibling file and list that, so the rest stays in the gate.
- **Render the component, not `<App>`**, unless the test is about navigation or the board: an `<App>` mount costs about 1 s per test in jsdom.
